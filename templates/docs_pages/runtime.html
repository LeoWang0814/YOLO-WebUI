Device selection

Auto
Lets Ultralytics choose a compatible execution device. The Workbench blocks Auto when the installed PyTorch wheel cannot execute on a detected GPU.
CPU
Forces CPU inference or training; expect slower training and inference.
Single GPU
Uses one compatible CUDA device by numeric index.
Multiple GPUs
Passes selected compatible CUDA device indices to the CLI. AutoBatch (batch=-1) and rectangular training (rect=True) are not supported for multiple GPUs, so use a positive batch size and leave rectangular training disabled.

Performance controls

Batch size and image size are the biggest memory and throughput controls. Workers affect data loading; reduce them on resource-constrained machines. Advanced options such as AMP, cache, half precision, video stride, and stream buffering should be changed one at a time and observed in the log and output quality.

Run queue

The application permits one active local Ultralytics process. This prevents a training and prediction process from competing for the same GPU, model files, logs, and output resources. A new request receives a visible conflict until the active run reaches a terminal state.

Model downloads

Pretrained downloads report percentage when the source exposes a content length, otherwise transfer activity. The final checksum phase can remain indeterminate while the file is verified. A valid verified file is reused from weights/ on later runs.
