Data lifecycle

Every browser upload uses the current Workbench address and a persistent session. The browser hashes the file incrementally, sends sequential 8 MiB chunks with a resumable byte offset, retries transient failures, and the server verifies the complete SHA-256 before finalization. Dataset ZIPs then extract into persistent dataset storage; model uploads are copied into models/; prediction media is hard-linked or copied into the run's source directory. The prepared cache hard-links source images where the filesystem permits or makes byte-for-byte copies otherwise. Generated run metadata records arguments, command text, runtime details, and logs.

Privacy and access

Dataset inspection, run execution, media processing, and artifact viewing happen on the machine hosting the Workbench. Dragging a ZIP dataset archive uploads it from the current browser to that machine for extraction; the app does not fetch remote prediction URLs. Pretrained model downloads are the only normal outbound network operation and use the configured catalog source. The application has no built-in authentication layer, so bind it only to an address appropriate for your environment.

Retention

Completed datasets, models, runs, and prepared datasets persist until removed from local storage. Incomplete upload sessions are retained for seven days by default so a browser refresh or temporary port-forward interruption can resume the same file, then their chunks and metadata are removed automatically. Set YOLOV10_UPLOAD_RETENTION_SECONDS to change the window. Deleting a source dataset does not remove its prepared cache automatically; deleting a prepared cache does not modify its source. Stop or close the Workbench before manually cleaning active run directories.
